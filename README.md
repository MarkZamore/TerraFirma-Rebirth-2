# TerraFirma Rebirth 2

Полная авторская `1.21.1-1.0.0-release`, Minecraft 1.21.1 / NeoForge 21.1.248,
для LANMinecraft. Источник — [официальный выпуск Granni_Xie / TFCR Dev Team](https://www.curseforge.com/minecraft/modpacks/terrafirma-rebirth/files/8843176).
Архив: 489 344 319 байт, SHA256 `51fc02aaee49ed9668e97923f9b4714acb5bf1fb4fe6f225652e4e2874372d19`.

Все 209 файлов manifest и 13 встроенных JAR сохранены: 222 основных JAR.
Каждый из 2 913 авторских файлов совпадает с оригиналом по размеру и SHA256.
В составе остаются CustomSkinLoader, Euphoria Patcher, Voxy/Roxy, авторские
конфиги, скрипты, музыка, ресурсы и шейдеры. Авторские JAR не заменены и не исключены.

Стабильный ID — `terrafirma-rebirth`, опубликованный путь — `TerraFirma Rebirth`,
источник обновлений — `MarkZamore/TerraFirma-Rebirth-2`. Видимое название не
переносит и не пересоздаёт личные миры.

## Подготовка для лаунчера

Проверено 30 октября 2026 года с лаунчером 420; точный коммит и границы
проверки указаны в runtime-отчёте ниже.

Авторский `options.txt` сохранён в исходниках и побайтово скопирован в
`configureddefaults/options.txt`. Кнопка управления использует его, только
когда личных настроек ещё нет. В существующем файле меняются назначения клавиш,
остальные параметры сохраняются. Прежний дополнительный seed языка удалён;
авторские переводы квестов остаются без изменений.

Пресет содержит ровно 216 действий из настоящего Options-реестра игры.
88 назначений используют различные физические клавиши, 128 строк свободны.
Пять прежних свободных строк вне Options удалены; все 88 назначений сохранены.
Авторский `options.txt` остаётся побайтово неизменным. Настоящие
InputConstants/KeyMapping NeoForge 21.1.248 под Java 21 проверили исходный
пресет и 3 828 пар назначений без конфликтов; окончательный набор является его
подмножеством и совпадает со всеми 216 нативными редактируемыми действиями.
Публикация проверяет закреплённый нативный реестр и точные исходные JAR;
статическое сканирование служит поиском новых действий. Руководство и происхождение:
[tools/keybinds/design.md](tools/keybinds/design.md).

Общий транспорт Steam и адаптер идентичности устанавливаются лаунчером в
экземпляр игры. В исходной папке `mods` остаются только 222 авторских JAR.
Данные поставки включают описание платформы, пресет, копию авторских начальных
настроек и ownership для полного авторского `config/fml.toml`.
Дальность и качество остаются авторскими и личными.
Заголовок окна `TerraFirma Rebirth 2` задаётся одной JVM-строкой сборки;
стабильный ID, опубликованный путь, имена экземпляров и миры не переименованы.

Для CustomSkinLoader сохранены его авторский JAR и обязательные проверки.
`config/native-version-metadata.jar` содержит только исходный 357-байтовый
`version.json` Minecraft, без классов, mod descriptors и агентов. Одна строка
`-Xbootclasspath/a:config/native-version-metadata.jar` делает родные метаданные
видимыми системному classloader. Это данные самой сборки, подготовленные из
закреплённого исходного client JAR; общего переписывания модов в лаунчере нет.
Инструмент, проверка при обновлении платформы и границы:
[tools/native-version-metadata/README.md](tools/native-version-metadata/README.md).

В авторском экспорте есть Euphoria Patcher 1.9.3 и настройки Complementary
r5.8.1, но отсутствуют требуемые базовые ZIP Complementary. Это вызывало видимое
красное уведомление Sodium поверх меню. Добавлены два точных официальных
входных файла `ComplementaryUnbound_r5.8.1.zip` и
`ComplementaryReimagined_r5.8.1.zip`; неизменённый авторский Patcher создаёт
свои пакеты штатно. Происхождение, размеры и SHA256/SHA512:
[native-required-shader-inputs.json](tools/author-source/native-required-shader-inputs.json).
Моды не обновлены, обычные журналы ошибок сохранены, авторский `enableShaders=false`
и остальные параметры качества сохранены. Эти два дополнения явно входят в
support-поставку, а не выдаются за содержимое исходного архива.

`config/log4j2.xml` и одна строка `launcher/jvm-args.txt` сохраняют прежний общий
журнал как данные сборки. Шаблон SHA256
`9e7b9918b6ede54f7393ed3d307e51a2edb032b98c12f069f5df976bcf940b89`
проверен по настоящим сетевым обработчикам и библиотекам Log4j; обычные
INFO/WARN/ERROR сохранены, а четыре пойманных сетевых исключения дополнены стеками. JVM-параметр сборки применяется после нативных значений.

Авторский `servers.dat` сохранён в исходниках как часть снимка, но не включён
в runtime-поставку: личный список серверов принадлежит экземпляру игры.
Личные миры и настройки при подготовке не читались и не копировались.

## Метки игроков хоста и конфигурация LSS

Слой совместимости JourneyMap обновляет существующие видимые записи радара
хоста по настоящим клиентским сущностям через публичный API мода. При замене
объектов игроков он сбрасывает только временный набор отображаемых лиц.
Сохранённые точки и изображения карты в эту операцию не входят.

Авторский `vss-server-config.json` использует старые названия параметров,
которые LSS 0.14.0 игнорирует при загрузке. Однократный pack-owned слой
переносит совместимые значения в штатные поля LSS. Подготовка и публикация
проверяют точные скрипты и JAR по `tools/host-compatibility-policy.json`.
При авторском обновлении сохраняются шаблоны и инструменты из раздела
`AGENTS.md`, затем выполняются `host_compatibility_policy.py prepare --apply`
и `verify`. Проверка отказывается принимать неизвестные версии автоматически.

Приёмка сохранена в `tools/qa/host-fixes-report.json`. Проверены исходные
байты, 86 автоматических случаев, настоящий Rhino и миграция LSS в отдельном
клиенте до меню и формы нового мира. По решению пользователя игровой прогон
пропущен. Поведение меток в мире и двухклиентный эффект на задержки не отмечены
как PASS. Отдельный native-пробник меток предназначен только для стенда и
не включается в поставку.

## Всплывающие сообщения Euphoria Patcher

Локальное правило сборки отключает `[display].doPopUpLogging` через штатный
конфиг Euphoria Patcher. Оно скрывает все popup-сообщения патчера, включая
предупреждения и ошибки; обычные файловые/консольные логи остаются. Подготовка
шейдеров, остальные параметры патчера, `doDisplayShaderInGameMessage` и
авторский выбор качества не меняются.

[tools/pack-config-overrides.json](tools/pack-config-overrides.json) хранится
отдельно от авторского конфига. Генератор применяет правило к байтам поставки
перед вычислением SHA256 и упаковкой ZIP, не редактируя исходные 2 913 авторских
файлов. Тем самым проверка точных авторских исходников сохраняется, а runtime
поставка явно отличается ровно одним boolean в одном авторском конфиге.
`pack-manifest.json:configOverrides` показывает исходные и поставляемые хеши.
Для текущей 1.0.0:

- исходный `config/euphoria_patcher/settings.toml`: 2 641 байт, SHA256 `d4ff06f1b6d8b191853b72996f8ba1d20cc90fa4e98e3222ab7fe552cf52b31e`;
- поставляемый конфиг: 2 642 байта, SHA256 `e72387a3fa1329b3c7d07d74dcf71e4ed58e3e0b35529e58ae561fcb61a25d94`.

При обновлении от автора обновляются исходники, исходный manifest и stock/lock;
локальное правило сохраняется. Обычный `tools/generate_manifest.py` повторно
применяет его и к новой авторской версии, сохраняя все остальные байты конфига.
Workflow проверяет наличие и корректность правила. Отсутствующий, дублирующийся,
переименованный или изменивший тип ключ прерывает публикацию вместо тихого
возврата popup. Полные новые авторские настройки не заменяются старой копией.

Конфиг не добавляется в `launcher/pack-owned.txt`: это перезаписало бы остальные
личные настройки Euphoria. Существующая изменённая личная копия сохраняется
обычным слиянием лаунчера; для её отключения применяется однократная правка
только этого boolean. Проверки и сценарий новой авторской версии описаны в
[tools/test_config_overrides.py](tools/test_config_overrides.py) и
[tools/test_generate_manifest.py](tools/test_generate_manifest.py).

Новых JAR или способов изменения мира нет; Safety не меняется. Исключений или
контентных правил в лаунчере для этого изменения нет. Игровой прогон для этой
настройки не заявляется; исторический runtime-отчёт ниже относится к прежней
поставке и не является проверкой новой настройки.

эти отдельные функции. Собственная политика Safety из ATM9 Modified на TFR
не распространяется.

Автор называет 1.0 преемником 4.1.24-hotfix2. Перенос прежних личных миров из
нашей 4.1.21 без утраты старых registry ID не проверялся. Личные файлы и миры
хранятся отдельно от обновляемой сборки.

## Ограниченная диагностика сетевых исключений

`config/log4j2.xml` сохраняет полные стеки четырёх пойманных сетевых исключений
`net.minecraft.network.Connection` в существующем `logs/latest.log`. Обычные
INFO/WARN/ERROR сохранены; остальные DEBUG, включая поток пакетов, отклоняются.
Отдельный `debug.log` не создаётся. Прежние пределы ротации сохранены: 32 МБ,
пять архивов и удаление архивов старше семи дней. Здоровое соединение не добавляет
этих диагностических событий. Это диагностика, а не исправление обрыва связи.

Конфиг закреплён как точный `config/log4j2.xml` в `launcher/pack-owned.txt`;
остальные личные конфиги этим правилом не охвачены. Перед заменой отличающейся
личной копии обычное обновление лаунчера сохраняет её в PackConflicts. Выбор
конфига уже находится в `launcher/jvm-args.txt`; новых правил C# при запуске нет.

После ручного переноса новой авторской версии сохраняют `config/log4j2.xml`,
`launcher/jvm-args.txt`, `launcher/pack-owned.txt`, `tools/network_logging_policy.py`
и `tools/network-logging-policy.json`. Затем в независимой исходной копии выполняют:

```text
python -B tools/network_logging_policy.py prepare --pack .
python -B tools/network_logging_policy.py verify --pack .
python -B -m unittest discover -s tools -p test_logging_policy.py
```

`prepare` применяется только при подготовке исходников, сохраняет остальные
JVM-параметры и обновляет квитанцию политики. Генератор поставки проверяет XML,
точный выбор JVM, ownership и квитанцию как перед упаковкой, так и в режиме
проверки. Удаление или повреждение правила останавливает публикацию, а не
возвращает молча прежнее логирование. Автоматическое обновление авторской сборки
без подготовки исходников здесь не заявляется. Новые версии игры и загрузчика
требуют повторной проверки настоящего сетевого обработчика.

[Подтверждения](tools/network-logging-proof/README.md) содержат точные SHA256
нативных классов и проверки фильтра настоящими Log4j 2.19.0, 2.22.1 и 2.26.0.
Игровой прогон этим изменением не выполнялся. JAR, графика, механики и пути
изменения мира не меняются; новая проверка Safety не требуется.


## Привязка меток JourneyMap к миру

Скрипт самой сборки связывает одиночные миры с устойчивыми UUID и сохраняет вытесненные метки в локальном архиве. Проверены настоящие Rhino/KubeJS и штатная Windows-ссылка папки saves; существующие миры и неоднозначные старые метки принимаются без удаления. [Точные версии и границы](tools/journeymap-waypoints-policy.json), [native API](tools/qa/journeymap-native-1211.json). Это данные сборки, а не запись конфигов лаунчером. Полный игровой прогон NeoForge этой поставки не объявляется выполненным.

После авторского импорта сохраните `tools/waypoint_source_policy.py`, receipt и шаблон; затем выполните `python -B tools/waypoint_source_policy.py prepare --pack . --apply` и `verify --pack .`. Генератор проверяет слой read-only до упаковки. Новая версия JourneyMap/KubeJS/Rhino требует проверки native API и обновления точных pins; произвольный совпавший файл не перезаписывается.


## Исправление первого лица на Intel

Отдельный pack-owned startup-скрипт восстанавливает штатную очистку глубины
first-person framebuffer Veil на Intel. В отдельном OpenGL-тесте на Arc B390
с драйвером 32.0.101.8724 именованная очистка непривязанного depth-stencil target
оставляла прежнюю глубину, а обычная очистка привязанного target давала 1.0.
Нативный клиент воспроизвёл нулевую глубину перед рукой. Скрипт повторяет только
эту очистку один раз перед первой рукой кадра, сохраняя stencil, свет и штатные
рендереры предметов. Шейдерный путь и другие GPU отсеиваются проверками.

Все 222 авторских JAR и 2 913 авторских файла сохранены побайтово. Новых JAR,
registry ID, ограничений качества или дальности нет. Скрипт поставляется отдельно
от author stock и принадлежит точному пути в `launcher/pack-owned.txt`.
Изменений или исключений в лаунчере для него нет; новый EXE не нужен.

Финальные байты загрузились настоящими KubeJS/Rhino в независимом клиенте с
новым миром TFC. Пользователь подтвердил отображение и разрешил фиксацию.
Полная независимая визуальная последовательность пустой руки, двух предметов
и повторного входа была прервана; автоматические contract-тесты не выдаются за
визуальную проверку двух LAN-клиентов. Границы, точные хеши и оставшиеся ERROR:
[отчёт](tools/hand-depth/runtime-report.json).

После авторского импорта слой сохраняется и проверяется по правилам
[tools/hand-depth/README.md](tools/hand-depth/README.md). В исходной независимой
копии выполняют `prepare --pack . --apply`, затем `verify --pack .` через
`tools/hand_depth_policy.py`. Генерация и публикация вызывают read-only verify:
потерянный слой, изменённые pins или неизвестная замена скрипта останавливают
поставку. Новая версия платформы, Sable/Veil, KubeJS или Rhino требует повторной
проверки и явного обновления pins. Остальные локальные слои сохраняются.
